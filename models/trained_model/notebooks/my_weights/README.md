# IngExuity LoRA Adapter — Model Card

## Model Overview

This is a LoRA (Low-Rank Adaptation) fine-tune of [meta-llama/Llama-3.2-1B-Instruct](https://huggingface.co/meta-llama/Llama-3.2-1B-Instruct), trained to serve as the inference backbone for IngExuity — a life partner AI that predicts user needs before they ask and stays present during emotional moments.

The adapter is trained with QLoRA (4-bit quantization) and targets all linear layers for maximum adaptation capacity while keeping trainable parameter count minimal.

## Uses

### Direct Use

This LoRA adapter is loaded on top of the Llama 3.2 base model and serves as the primary inference engine for IngExuity. It is used through the IngExuity Julia package:

```julia
using IngExuity
TrainedModel.load_trained_model()
chat("Hello, how are you?")
```

The adapter shapes the model's outputs to better fit IngExuity's personality and conversation style — empathetic, direct, prediction-first.

### Downstream Use

IngExuity uses this model to:
- Power conversation responses in a prediction-first architecture
- Stay actively engaged during emotionally charged conversations
- Generate responses shaped by learned user patterns

### Out-of-Scope Use

This adapter was trained for conversational AI and may not perform well for:
- Code generation or technical tasks (base model is not specialized)
- Non-English languages
- High-stakes decision making requiring factual accuracy
- Tasks requiring up-to-date information (knowledge cutoff limited by base model)

---

## Bias, Risks, and Limitations

### Technical Limitations

1. **Knowledge cutoff:** Based on Llama 3.2 1B which has knowledge cutoff limitations
2. **Hallucination risk:** Like all LLMs, may generate plausible but incorrect information
3. **Context window:** 128K tokens (base model supports long context)
4. **Parameter efficiency:** LoRA adaptation may not capture all nuances of desired personality

### Sociotechnical Limitations

1. **Personality shaping:** The adapter shapes responses to fit IngExuity's empathetic, direct style — users should be aware responses are generated by AI, not human
2. **Emotional support:** While the model is designed to stay present during emotional moments, it is not a replacement for human mental health support
3. **Prediction accuracy:** Predictions about user needs are probabilistic and may be incorrect

### Recommendations

- Do not use for medical, legal, or financial advice
- Users should maintain awareness they are interacting with AI
- Predictions should be validated, especially for important decisions
- The model should not be used as a substitute for professional mental health support

## How to Get Started

### In Python (HuggingFace)

```python
from peft import PeftModel, PeftConfig
from transformers import AutoModelForCausalLM, AutoTokenizer

# Load adapter config
config = PeftConfig.from_pretrained("path/to/adapter_config.json")

# Load base model and tokenizer
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3.2-1B-Instruct")
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-3.2-1B-Instruct")

# Load LoRA adapter
model = PeftModel.from_pretrained(model, "path/to/adapter_weights")

# Generate
inputs = tokenizer("Hello, how are you?", return_tensors="pt")
outputs = model.generate(**inputs, max_new_tokens=100)
print(tokenizer.decode(outputs[0], skip_special_tokens=True))
```

### Export to GGUF for Julia

```bash
# Install dependencies
pip install -r requirements.txt

# Export PEFT adapter → GGUF
python python/export_to_gguf.py \
    --model_path ./models/trained_model/notebooks/my_weights \
    --output ./models/llama3-finetuned.Q4_K_M.gguf
```

### In Julia (IngExuity)

```julia
using IngExuity
using TrainedModel

load_trained_model()
response = chat("Hello, how are you?")
```

## Evaluation

### Evaluation Approach

IngExuity is evaluated by:
1. **Conversation quality:** Does the model stay on-brand (empathetic, direct, prediction-first)?
2. **Presencing accuracy:** Does the model correctly stay present when stress/emotional_charge/valence thresholds are met?
3. **Prediction accuracy:** Does the system anticipate user needs before they articulate them?
4. **User model fidelity:** How well does the learned user model match actual user behavior?

### Factors

- Emotional tone matching
- Prediction accuracy over time
- Response directness vs. fluff
- Staying present vs. jumping to solutions

---

## Model Examination

The LoRA adapter modifies attention and FFN layers. Key observations:
- All linear layers targeted (q, k, v, o, gate, up, down projections)
- Rank 32 provides good balance of adaptation capacity vs. parameter efficiency
- Alpha 64 (2x rank) provides stronger adaptation scaling

## Technical Specifications

### Model Architecture

- **Base architecture:** Llama 3 (Llama 3.2 1B)
- **Attention:** Self-attention with LoRA adapters on Q, K, V, O projections
- **FFN:** SwiGLU with LoRA adapters on gate, up, down projections
- **Position encoding:** RoPE (rotary position embeddings)

### Compute Infrastructure

| Component | Specification |
|-----------|--------------|
| Training GPU | Kaggle P100 (16GB) or equivalent |
| Inference | CPU or GPU, quantized GGUF |
| Framework | PEFT 0.6.2, bitsandbytes |
